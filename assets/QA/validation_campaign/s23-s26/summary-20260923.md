The screenshot-reported overflow defect was fixed in the Dataset row styles and path binding. The UI regression now checks row geometry, computed `nowrap`/`hidden`/`ellipsis`/`min-width:0`, the full path title, and viewer navigation. Screenshots are 1920×1080; their SHA-256 values are in [UI observations](s23-ui-observations.json): [contained long-path row](s23-long-source-path-row.png), [viewer image 1](s23-image-viewer-first.png), [viewer image 2](s23-image-viewer-next.png).

The first training attempt, job `29f7392a`, failed with `No training metadata found`. Investigation showed `load_environment(override=True)` replaced a process-supplied `XREPORT_RESOURCES_DIR` after the parent resolved its runtime paths; the spawned worker then selected the default database rather than the disposable one. The environment loader now preserves the explicit process-level resource root, with a focused regression test. This was required to make isolated spawned training deterministic and keep it away from canonical resources.

`ISSUE-003` came from checkpoint E2E fixtures writing `{}` as `session_history.json`; checkpoint completeness checks then warned, and API cleanup could leave the registry entry behind. The fixtures now include valid one-epoch history; cleanup reconciles both registry and files; tests assert listing removal and referenced-checkpoint rejection. The focused suite ended with no `e2e_delete_*` registry entries, no matching incomplete-checkpoint warnings, no FK violations, and SQLite integrity `ok`. Detailed root-cause evidence is in [issue-003.json](issue-003.json).
