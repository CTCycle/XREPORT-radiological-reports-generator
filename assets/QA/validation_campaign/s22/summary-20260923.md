# S22 Dataset Processing and Integrity Validation

Last updated: 2026-09-23

## Result

**Status: PASS** for sampling, train/validation persistence, tokenizer
selection, missing-image failure, repeated processed-name handling, and
processing metadata after backend restart. Validation ran on `develop`, based
on commit `2a6e65a1affa997c572641f0ed038863eefc0161`, with the S21/S22
implementation and test changes present in the working tree. The exact
committed source/test revision is recorded in the campaign ledger after commit.

## Scenarios and results

- The rendered Dataset page exposed exactly the supported tokenizer choices:
  `distilbert-base-uncased`, `bert-base-uncased`, and `roberta-base`.
- Processing the eight-row source at `sample_size=0.5`,
  `validation_size=0.25`, and `max_report_size=50` completed with four retained
  samples: three train and one validation.
- A second run with the same custom processed name and `sample_size=1.0`
  completed with eight samples: six train and two validation. The processed
  names API exposed one identity with row count eight. SQLite retained two
  `processing_runs` for that identity, with their distinct sample sizes and
  split counts.
- After deleting the image file from a separate one-row synthetic source,
  processing failed with the missing/invalid image-path error before
  tokenization and did not produce a processed dataset.
- The existing minimum-one sampling regression passed:
  `test_fractional_sampling_retains_one_row_for_small_nonempty_dataset`
  (**1 passed, 9 deselected**).
- The isolated backend was stopped and relaunched by the official launcher
  with the same resources root. After restart, the API returned the eight-row
  source, one processed-name identity, and latest metadata (`sample_size=1.0`,
  `validation_size=0.25`, the selected tokenizer, and vocabulary size `30522`).
  Direct SQLite inspection still found both processing runs; `PRAGMA
  integrity_check` returned `ok`.

## Remaining limitations

This is functional evidence on an eight-row synthetic fixture. Per-run wall
time and peak memory were not instrumented, so it makes no performance claim.
It does not cover large or real-world corpora, packaged desktop execution,
dataset viewer/deletion, training/checkpoint creation, or downstream clinical
quality. Those remain separate validation gates.
