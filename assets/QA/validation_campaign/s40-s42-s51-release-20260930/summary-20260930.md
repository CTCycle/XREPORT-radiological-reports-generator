## Harness and release safeguards

`app/scripts/validate_resilience_baseline.py` is now schema v2 and supports:

- `--execution-lane cuda|cpu|unavailable-gpu` without duplicate scenario
  definitions;
- `--fixture-scale`, explicit dataset/processed-dataset/checkpoint names, and
  `--start-mode clean|warm` metadata;
- expected terminal statuses, worker PID/phase/first-progress/first-batch
  observations, per-worker process samples where measurable, nonterminal-job
  detection, bounded stranded-job cancellation, and reconciliation data;
- device provenance assertions for CUDA, CPU, and the documented no-GPU
  fallback lane.

The deterministic plan-only check passed for the scale-8 unavailable-GPU lane:
eight S51 scenarios, six GPU-requested training operations, and one explicit
`cancelled` terminal assertion. The focused unit/packaging suite passed `26`
tests; Ruff passed for all modified Python files. These are implementation
checks, not live S51 acceptance evidence. The CPU, unavailable-GPU, scale-8,
packaged, and native active-close S51 matrices remain to be run on the final
committed revision.

The release workflow now declares the `release-approval` environment and
requires `assets/QA/validation_campaign/release-validation/approved-release-
manifest.json` to bind the exact source SHA, version, approval identity/time,
validation record, and all eight CPU/CUDA release asset hashes. The reusable
verifier is `app/desktop/build/verify_release_validation_manifest.py`.

## Regression boundary

The documented full Windows runner was also executed, but it was not green:
`166 passed, 3 skipped, 8 failed, 58 errors`. The errors were Windows access
denials while creating the runner's temporary pytest cache, the eight failures
were access denials writing pre-existing QA screenshot paths, and the Angular
E2E bootstrap could not create its temporary cache directory. The runner left
a preview/backend process behind; its exact task-owned PIDs were terminated
and ports `5003`/`8003` were rechecked as closed. This is recorded as an
environmental regression-run failure, not as full-suite release evidence.

Independent checks on the candidate source passed: the Angular production
build, frontend lint, Pyright, Rust `cargo check`, the focused unit/packaging
suite, Ruff, PowerShell parsing, and the native WebView driver. These checks
do not replace the failed full-runner result or the unrun release lanes.

## S42 and final release boundaries

Prior evidence still establishes one real packaged CUDA inference on the RTX
3060 with CUDA provenance. This working-tree campaign did not rebuild portable
or MSI artifacts, did not run the package on genuinely GPU-less hardware, and
did not repair the canonical CXRMate Multi resource (`ISSUE-006`). S42 remains

unauthorized (`S37`/`ISSUE-002`). The release record cannot become approved
