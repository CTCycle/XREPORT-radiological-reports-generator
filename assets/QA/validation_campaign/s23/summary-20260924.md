## Outcome

The 2026-09-23 S23 run found that deleting a source dataset returned success,
then cascaded its records and emptied a surviving processed dataset. The new
regression test reproduced the missing conflict before the fix.

Source deletion now returns HTTP 409 and names any dependent processed datasets.
The source dataset, processed dataset, source record, and training sample remain
present after that response. `DatasetRepository.load_training_data()` then
returns the one expected training row with its image name, report text, and
image path. After deleting the processed dataset first, deleting the source
returns HTTP 200; dataset, record, processing-run, and training-sample tables
are empty, `PRAGMA foreign_key_check` returns no rows, and
`PRAGMA integrity_check` returns `ok`.

The viewer and long-path containment remain covered by the rendered S23 browser
evidence in the [S23–S26 summary](../s23-s26/summary-20260923.md). This
follow-up did not capture a new browser screenshot of the rejected-delete
message.
