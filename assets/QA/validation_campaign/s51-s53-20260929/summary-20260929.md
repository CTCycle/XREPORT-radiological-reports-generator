## Browser lifecycle

Using the Codex in-app Browser during the live run, Dataset, Training, and Reports were opened in sequence. Dataset rendered the eight-row source fixture and processing controls; Training rendered its live dashboard and checkpoint list while a training job was active; Reports rendered the saved successful session. Reports was reloaded, then the browser tab was closed and reopened on Training. The reopened page reached `Idle` and showed completed checkpoints and processed datasets without a stale active worker. The active-run captures were inspected inline; the route-refresh E2E saved durable screenshots in this campaign directory.

Native Tauri/WebView interaction remains excluded because no targetable native window was exposed.

## Setup and limitations

The first attempt was intentionally preserved as evidence. It found only disposable-clone setup problems: the cloned checkpoint row referenced the prior disposable absolute path, and the task clone lacked the pinned `XRAYEncoder` cache. The task-owned database path and cache were repaired; canonical `data/`, model resources, and protected historical cache paths were not modified. The subsequent source-launch run completed the intended matrix.

The cold first triple's training worker exited with code `1` while validation and checkpoint evaluation completed; later two triples and the repeat matrix completed. No production fix was made because the failure did not reproduce and the available evidence does not identify a safe service defect. Broader GPU/resource stress, representative data, scale, packaged/no-GPU comparison, native WebView, spoken accessibility output, MedGemma access, canonical model repair, and protected-cache ownership remain explicitly outside this slice.

The final official launcher smoke returned `200` for backend health, frontend proxy health, and frontend root serving. The official `KillProcesses` helper returned `Access denied` during Windows process inspection; the exact remaining task-owned launcher PIDs (`3688`, `13412`) were stopped after verification and listeners on ports `5003` and `8003` were confirmed absent. See [cleanup checks](cleanup-checks.json), [final launch log](source-launch-final-smoke.log), and [final cleanup log](kill-final.log).
