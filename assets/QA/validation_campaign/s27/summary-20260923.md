# S27 — Successful dataset validation

## Result

`S27` passes for full-dataset validation of a small, non-clinical synthetic
fixture. The run completed all three validation metric families, persisted a
report, and returned that report from the saved-report endpoint. The validation
route displayed the completed metrics and the report's saved timestamp in the
Codex in-app browser.

This is technical workflow evidence only. The eight-row generated corpus does
not support clinical, diagnostic-quality, representative-data, or scale claims.

## Scenarios and results

1. Uploaded `s27_technical_fixture.csv`: HTTP 200, eight rows and two columns.
2. Loaded it against the eight-image folder: HTTP 200, eight matched, zero
   unmatched.
3. Selected the full dataset and all three metric families, then completed the
   validation twice, including once against the rebuilt production bundle.
   Both jobs reached `completed` at 100% and returned `success: true`.
4. Retrieved the persisted report: HTTP 200; dataset name, full sample size,
   and metric list matched the run. The saved report contains eight text
   records, 104 total words, 20 unique words, eight 64 × 64 images, and 256
   pixel bins totaling 32,768 pixels.
5. Reviewed the completed route in the in-app browser. Before the fix, the
   completion modal showed `Generated: N/A` even though the saved report had a
   timestamp. The page now refreshes report metadata after completion; the
   rebuilt-bundle rerun displayed `Generated: 2026-09-23 21:38:24`.

The browser screenshot was captured and visually reviewed inline during the
task. The exposed in-app browser capture API did not provide a filesystem
export, so no standalone PNG is included. API responses and durable fixtures
are included below.

The persisted report's `artifacts` map is empty. This run verifies that the
selected metric values, metric list, sample size, and timestamp persist in the
database-backed report response; it does not verify separate metric files or
other generated file artifacts.

## Implementation change

`dataset.page.ts` now fetches saved report metadata after a validation job
completes and applies it only when the returned report belongs to the current
dataset. This supplies the authoritative persisted timestamp and report
metadata to the completion view. A regression test verifies the metadata fetch
and rendered completion data.
