## Scenarios observed

- **Full match:** the eight-row synthetic source used for S22 matched all eight
  images and imported with zero unmatched rows. Its CSV image stems used mixed
  case and `.jpg` while the image files used `.PNG`.
- **Partial match:** the rendered Dataset page showed one matched and one
  unmatched row. The API still showed no source dataset before confirmation.
  Clicking **Import matched rows** persisted one source row; the page then
  showed the confirmed one-row/one-unmatched result.
- **No match:** API load returned HTTP 400 with `No dataset rows matched`; no
  source dataset was persisted.
- **Required columns:** service tests rejected missing `image` and missing
  `text` columns while retaining the upload for correction/retry.
- **Source persistence:** the confirmed row retained its report text, CSV
  image name, and resolved image path in the image metadata API.
- **Case-insensitive stems:** `matched.jpg` matched `Matched.PNG`; the resolved
  path was persisted. This fixes the previously case-sensitive behavior using
  case-folded stem keys and lookups; there is no public API or schema change.

## Remaining limitations

The import fixtures are small and synthetic. This does not establish matching
quality for arbitrary naming conventions, large-corpus performance, packaged
desktop behavior, dataset viewing/deletion, training, or clinical report
quality. Those claims remain with their separate campaign gates.
