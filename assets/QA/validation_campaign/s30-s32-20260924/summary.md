## Commands and execution evidence

The official launcher command and resolved isolated root are recorded in [runtime observations](runtime-observations.json). Final pytest invocations used absolute campaign paths for `--basetemp` and `cache_dir`, with `PYTHONPYCACHEPREFIX` also isolated under the campaign cache root. The exact unit invocation and result are recorded in [unit-tests-final.log](unit-tests-final.log); it ran seven inference-focused modules and passed 55 tests. The API E2E invocation and result are recorded in [api-e2e-final.log](api-e2e-final.log); all six tests passed. [Ruff output](ruff-final.log) records lint success across all five changed Python files and format success on four; formatting the entire service module would create broad unrelated changes, so its changed lines were lint-checked without whole-file reformatting. Live health, model counts, empty job list, isolated resource root, and credential-presence booleans are in [runtime observations](runtime-observations.json).

The first API rerun used an isolated backend root but did not set the matching root in the pytest process. Its history fixture wrote to a different database, so one history test failed to find its seeded row. That run is preserved in [resource-root diagnostic](api-e2e-resource-root-diagnostic.log). The corrected rerun set the same root for both processes and passed all six tests. The earlier wrong-context diagnostic also remains preserved in [initial diagnostic](api-e2e-initial-diagnostic.log) with its [job snapshot](jobs-after-failure.json); it started an unintended CheXOne download in the isolated root, which was removed before the clean run. No canonical model store was modified.

The route now reads uploaded image data in bounded chunks and raises the existing typed 413 error as soon as aggregate bytes exceed the configured limit. The 64 MiB limit lives in `server.common.constants` and is imported by both the API and service, avoiding a method-local service import while keeping one shared value. Previously the route copied every upload into memory before the service enforced the limit. The E2E test streams the two-file over-limit request and repeated image parts through HTTPX; Playwright's dictionary multipart form cannot represent repeated file keys.

The API keeps its existing lazy service construction: its `TYPE_CHECKING` import supports annotations, and the service factory import stays inside the property so importing the router does not eagerly load the service graph. Those imports predate this slice and preserve the startup boundary.
